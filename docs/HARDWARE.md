# Hardware and approach

## The board (Super Kaneko Nova System, MAME `suprnova.cpp`)

| Part | Details | Implementation |
|---|---|---|
| CPU | Hitachi SH7604 (SH-2), 28.636 MHz | translated program + `runtime/src/sh2_*.c` |
| BIOS | 512 KiB at 0x00000000 (`sknsu1.u10`, USA); vectors, POST, region check | translated with the game |
| Game program | 2 MiB at 0x04000000 (two byte-interleaved 1 MiB ROMs) | translated |
| Main RAM | 1 MiB at 0x06000000; 4 KiB on-chip cache RAM at 0xC0000000 | `board.c` |
| NVRAM | 8 KiB battery-backed RAM at 0x00800000 (fresh: all 0xFF) | `board.c`, persisted by the frontend |
| Inputs | 0x00400000 (players, coins, service), 0x00400004 (test, DIPs) | `board.c` |
| RTC | MSM6242 at 0x01000000 (time from the host clock; fixed in the headless runner) | `board.c` |
| "Hit" unit | collision / math helper and region unlock at 0x02F00000 / 0x01800000 | `board.c` |
| Video | two 64x64 ROZ tilemaps of 16x16 tiles (8 or 4 bpp) with per-line or per-column scroll; RLE-compressed sprite generator with zoom, groups and chaining; 32,768-entry palette with separate sprite/background brightness and additive sprite blending | `video.c` |
| Sound | Yamaha YMZ280B, 16.6666 MHz, 8 voices of 4-bit ADPCM / 8-bit / 16-bit PCM from a 4 MiB sample ROM | `ymz280b.c` |
| Interrupts | IRQ 5 at vblank (line 240), IRQ 1 at line 0, periodic IRQ 15 (2 ms), IRQ 11 (8 ms), IRQ 9 (28.636 MHz / 1824) | `board.c` |
| On-chip | DIVU (32/64-bit divider), FRT (free-running timer; output compare A drives the sound driver at ~123 Hz, interrupt level 15), watchdog (kicked, never fires) | `board.c` |
| Screen | 320x240 visible, 340x262 total, 59.5971 Hz, monitor rotated 90° | frontend |

## Translator

`tools/sh2dec.py` decodes SH-2 opcodes following MAME's `execute_one`.
`tools/recompilesh2.py` walks the code from the vector tables, seeds, literal
pool code pointers (iterated to a fixed point) and pointer tables (runs of
three or more ROM pointers), keeps only plausible entry points (decodes to a
return/jump within 400 instructions without an illegal opcode), and emits one C
function per instruction, grouped into files of 16 KiB of address space plus a
hashed dispatch table.

- Delayed branches run their delay slot inline; a PC-relative load in a delay
  slot uses the slot's own address (checked on this ROM: the literal-pool
  values only make sense that way).
- Cycle accounting follows MAME's interpreter: one cycle per instruction plus
  the per-instruction extras of `sh.cpp`, +2 for taken BT/BF, +1 for taken
  BT/S and BF/S, branch/jump/return costs as in MAME, RTE +3, TRAPA +7.
- Interrupts are taken between instructions, exactly where MAME's interpreter
  checks them (after SR changes, RTE, and when a line is raised).
- MAME's Cyvern idle skip (spin at 0x0402EBD2 until an interrupt) is
  reproduced; it halves the host work and does not change the output.

The fallback interpreter (`runtime/src/sh2_interp.c`, generated by
`tools/make_sh2_interp.py`) is a 65,536-entry decode table over the same
semantic functions, with the same cycle and delay-slot rules. The recompiled
and generic builds produce identical per-frame RAM hashes, so the translator
and the interpreter cross-check each other.

## Video timing

As in MAME, the picture is composed at the start of vblank (line 240) from the
tilemaps and the sprite bitmap drawn at the previous vblank, then the sprites
for the next frame are drawn. The sprite bitmap is only cleared when the game
asks for it (sprite register 0x04 bit 2), which the game uses for trails.

## How it was verified

Against MAME 0.264 running the same ROMs (references made locally, not
distributed):

- **Screen:** pixel-identical at frames 60, 120, 300, 600, 900 and 1200 (BIOS
  check screens, region warning, Super Kaneko Nova logo, the game's warning and
  Kaneko logo) and with the Flip Screen DIP on at frames 1200 and 3000. From
  frame ~1450 the attract sequence runs about one frame behind MAME's, so later
  snapshots show the same scenes slightly out of phase.
- **Main RAM:** at frames 300 and 900, 2–3 bytes differ from MAME (interrupt
  counters); the BIOS's own interrupt counters show the translated BIOS starts
  counting about 2 ms (one 2 ms tick, 33 IRQ 9 ticks) later than MAME. MAME's
  own SH-2 DRC and interpreter disagree with each other by a similar amount
  (95 vs 84 IRQ 9 ticks at frame 6), so this is within the reference's own
  timing variance; the game-visible effect is the ~1 frame attract phase.
- **Audio:** MAME's `-wavwrite` recording of 80 s of attract mode vs ours:
  loudness envelope correlation 0.998 at the best alignment (50 ms), level ratio
  1.005; first note at 24.61 s (MAME) and 24.65 s (ours).
